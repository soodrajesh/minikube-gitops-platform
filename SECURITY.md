# Security

This is a local demo repo, not a hardened production platform. This document lists what's
actually implemented and enforced by the code in this repo, and what's explicitly out of scope.

## Implemented

- **Non-root containers**: `app/Dockerfile` and `greeter/Dockerfile` each create and run as a
  dedicated `appuser` (uid 1000). Both Deployments' `securityContext` additionally set
  `runAsNonRoot: true`, `allowPrivilegeEscalation: false`, `readOnlyRootFilesystem: true`, and
  drop all Linux capabilities.
- **Resource limits**: every container in this repo (both apps, and the monitoring components
  via `monitoring/values.yaml`) has both requests and limits set, to avoid one component
  starving the others on a small local cluster.
- **NetworkPolicy**: `gitops/sample-app/networkpolicy.yaml` default-denies all ingress traffic
  into the `app` namespace, then explicitly allows traffic from `ingress-nginx` (user-facing)
  and `monitoring` (Prometheus scraping). `gitops/greeter/networkpolicy.yaml` does the same for
  the `backend` namespace, allowing only the `app` namespace (to actually reach `/greet`) and
  `monitoring` — nothing else in the cluster, and nothing outside it, can reach `greeter`.
- **Policy-as-code (Gatekeeper)**: `gitops/policies/` codifies four of the conventions above as
  cluster-enforced admission policy, not just manifest convention — `K8sRequireNonRoot`,
  `K8sDisallowPrivilegeEscalation`, `K8sRequireResources`, `K8sDisallowLatestTag` — scoped to the
  `app` and `backend` namespaces only via `match.namespaces`. A pod that violates any of these
  in those namespaces is rejected at admission (`enforcementAction: deny`), not just linted.
- **No secrets committed to git**: ArgoCD's admin password and Grafana's admin password are
  both auto-generated by their respective Helm charts into Kubernetes Secrets at install time.
  Nothing in this repo hardcodes a password. `.gitignore` also excludes any local
  `secrets.yaml`/`config.yaml`/`*.kubeconfig` in case someone adds one.
- **TLS in transit (ingress)**: `gitops/tls/` bootstraps a local CA via cert-manager
  (`selfsigned-issuer` → `local-ca` Certificate → `ca-issuer` ClusterIssuer), and both
  `sample-app` and Grafana's Ingress get a real leaf certificate issued from it via the
  `cert-manager.io/cluster-issuer` annotation. `ingress-nginx` redirects plain HTTP to HTTPS by
  default once TLS is configured. This is real, working TLS termination and cert issuance — the
  gap is that the CA itself is self-signed locally, not from a publicly-trusted authority (see
  "Explicitly out of scope" below).
- **Image scanning in CI**: `.github/workflows/ci.yml` builds both apps' images and runs
  `aquasecurity/trivy-action` on each, failing the build on HIGH/CRITICAL fixable vulnerabilities.
- **Cluster-level smoke testing in CI**: `e2e-smoke-test` in `.github/workflows/ci.yml` stands up
  a `kind` cluster, applies the actual manifests (not through ArgoCD — see the job's comments),
  and verifies the app serves traffic, calls `greeter` across namespaces, and that Gatekeeper
  actually rejects a non-compliant pod. Catches real deployment bugs before merge, not just YAML
  syntax errors.
- **`automountServiceAccountToken: false`** on both apps' pods — neither needs to talk to the
  Kubernetes API, so neither gets a token to do so.
- **Least-privilege ArgoCD Applications**: each Application targets a specific namespace
  (`app`, `backend`, `monitoring`, or `gatekeeper-system`), not cluster-wide resources, and uses
  `CreateNamespace=true` rather than requiring pre-existing elevated access.

## Explicitly out of scope (aspirational, not implemented)

- **Secrets at rest**: Kubernetes Secrets are base64-encoded, not encrypted, by default on a
  stock cluster. A real deployment should add Sealed Secrets, External Secrets Operator, or
  Vault. None of that is wired up here.
- **Publicly-trusted TLS**: the cert-manager CA is self-signed and only trusted if you
  explicitly import `local-ca-secret`'s `ca.crt` — browsers will warn by default. There's no
  path to a real CA here (Let's Encrypt et al. need publicly-resolvable DNS, which `*.local`
  hosts don't have).
- **Gatekeeper coverage is intentionally narrow**: it only watches the `app`/`backend`
  namespaces, only checks 4 rules, and only enforces going forward — it doesn't retroactively
  flag or evict already-running pods that predate a constraint (Gatekeeper's audit controller
  would report them as violations on its next audit pass, but `enforcementAction: deny` only
  blocks admission of *new* create/update requests). It also doesn't cover the upstream ArgoCD
  or kube-prometheus-stack charts, which weren't written to these conventions and would break
  if the same constraints applied to them.
- **Service mesh**: no Istio/Linkerd, so no mTLS between pods, no fine-grained traffic policy
  beyond the two NetworkPolicies.
- **RBAC hardening beyond ArgoCD's defaults**: ArgoCD itself is installed with the chart's
  default RBAC; this repo doesn't add a custom least-privilege ArgoCD project/role beyond
  namespace-scoped destinations on each Application.
- **Runtime security monitoring**: no Falco or equivalent.
- **CI doesn't exercise the ArgoCD sync path**: `e2e-smoke-test` applies manifests directly on
  `kind`, not through ArgoCD, and skips `kube-prometheus-stack`/`ingress-nginx`/cert-manager
  entirely to fit a GitHub-hosted runner. The GitOps sync mechanics and the full stack are only
  tested by running `scripts/deploy.sh` + `scripts/test.sh` locally.

If you're adapting this for anything beyond a personal demo, treat the "implemented" list as a
floor, not a ceiling, and the "out of scope" list as the first things to add.
